DEPLOY-2b CRITERIA (final; do not rewrite)
1. Total-change audit: before/after predictions are produced from two DIFFERENT code versions (the pre-deploy1 tag or zip, and the current code) on Format A tune, Format B tune and v3-44; a per-sheet table lists every sheet whose grand-total value, flags or sum status changed (label, before read and flags, after read and flags, sum statuses), with counts of sheets fixed, broken and changed only in flags, and the code change responsible (file and rule name); the origin and introduction point of the RECOVERED_FROM_CELL_CONSENSUS and SUGGESTED_FROM_CELLS paths are stated.
2. Independence of the sum gate: no sheet whose grand total was set or recovered from the question cells has sum status AGREE (count shown, must be 0); DISTINCT erroneous AGREE sheets, silent wrong grand totals and silent wrong cells are reported before and after per set; grand-total exact is reported both counting recovered totals and excluding them; silent wrong totals are not more than 1 sheet above the FINAL2 level on each set.
3. Concurrency: 60-sheet jobs (30 tune A + 30 tune B, 2000 px JPEG q90) for (WORKERS, ORT_THREADS) = (1,4), (2,2), (2,4), (3,2): elapsed, sheets per second and peak RSS per configuration, plus a sheets-per-hour capacity estimate for one job and for 3 concurrent jobs.
4. Shutdown: a test that sends a termination signal during a job (or the closest Windows equivalent, stated) shows the documented behaviour (running sheets finish or the job is marked failed or requeued) and that new uploads are refused; the result is shown.
5. Privacy, HTTPS and headers evidence: docs/PRIVACY.md exists (listing shown); the Caddy or reverse-proxy profile and Caddyfile exist; tests show CORS rejects an origin not in CORS_ORIGINS, secure response headers are present, and uploaded files are not reachable through any static route.
6. Keys and drills: tests show a revoked key returns 401 on its next request; key hashing is described (algorithm, salt or high-entropy rationale) with the code reference; test names and counts are listed for the authentication, upload, privacy and operations tests.
7. Web UI CSV: the real CSV-building function of frontend/app.js is run (node or jsdom if available) with a declared subject code and the header and first rows are shown; otherwise NOT EVALUATED with the reason.
8. Docker and fresh environment: any item that cannot be run in this environment is reported as NOT EVALUATED with the reason; docs/DEPLOY_ON_SERVER.md gives the exact commands (docker build, compose up, /ready, identity check, fresh venv with pip freeze) for the human.
9. Re-freeze: if any code, config or model changed in this milestone, the manifest is regenerated and the 15-sheet identity check (differences only as documented in part 1) and the tune regression are re-run; tests pass with counts shown; scripts/check_imports.py passes; v4 was not touched.
