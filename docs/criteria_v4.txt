v4 ACCEPTANCE CRITERIA (final; fixed before the run)
1. Integrity: manifest verified at run time and its hash recorded; the run happens once (lock file); no code, config or model change afterwards; labels file hash recorded.
2. Layout: on sheets with framing = ok, the detected layout equals the layout column on >= 95% of sheets; zero wrong-layout sheets return values anywhere in v4 (UNKNOWN is allowed).
3. Enrolment (framing = ok): tail-4 exact >= 88% per detected layout, and wrong, unflagged enrolments after batch flags <= 8% of sheets.
4. Grand total (framing = ok): value-only exact >= 75% (a total derived from the question cells is a suggestion and does not count as the value; suggestions are reported separately), and wrong, unflagged totals <= 6% of sheets.
5. Question cells (framing = ok, cells not marked unreadable): exact on unflagged cells >= 93% (Format A) or >= 96% (Format B); flagged share <= 30% (A) or <= 15% (B); silent wrong cells <= 6% (A) or <= 4% (B).
6. Sum gate: at most 2 distinct sheets under AGREE with any wrong cell or total; no sheet with a derived total has sum status AGREE.
7. Uncropped sheets (framing = uncropped): zero wrong-layout sheets return values; wrong, unflagged enrolments or totals <= 10% of those sheets; the shares read, UNKNOWN, PARTIAL_SHEET and rescan are reported.
8. Unreadable cells: the share flagged is reported; a confident value on an unreadable cell counts as a silent wrong cell.
9. Subject code: the per-sheet read is reported and not scored (the sealed runner has no declared-code option; the declared-code behaviour is covered by the API tests).
10. Latency (single-sheet endpoint, input as given, decode included): mean <= 2.5 s and P95 <= 3.5 s; job throughput is reported.
11. Reported, not scored: AGREE share, needs-review share, rescan share, PARTIAL_SHEET share, per-layout and per-framing counts.
